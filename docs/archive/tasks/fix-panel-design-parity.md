# 菜单栏面板照设计稿 v0.2 排版：圆形线路开关、分隔线分区、整宽的聚合方式

## 问题

2026-11-19 作者反馈界面与设计稿差别太大（同 `fix-overview-design-parity`）。对已安装构建的面板截屏对照设计稿「菜单栏」一节：

- 三个分区各套一个分组表单的底框，分区标题偏大；设计稿是平铺的行，分区之间一条细分隔线。
- 线路行用右侧的小开关；设计稿是左侧 28 pt 的圆形开关（启用时填线路色），右侧是速率 / 待命 / 已停用，主备下名称后带「主」「备」。
- 迷你流向图 44 pt 高、速率占一列；设计稿是 64 pt 高的条，速率叠在右上角。
- 聚合方式的分段控件缩在中间；设计稿占满宽度。「聚合服务器」一行设计稿只在叠加时出现。
- 出口区第一行叫「模式」；设计稿叫「路由」（词表也不让单说「模式」）。

`4e87348` 把面板改成分组表单，依据是 `copy-and-style.md` §2「内容区用 Form(.grouped)，不自己拼卡片」。两条依据冲突时本卡这样取：控件仍然全用系统控件（按钮样式的 Toggle、NSSegmentedControl、Menu、Picker、NavigationLink），排版照设计稿。面板是弹出面板而不是内容区，§2 那一条说的是主窗口页面。请作者确认这个取舍。实现中发现的一处例外：线路的圆形开关是自己画的（`RoundSwitchStyle`）——系统的按钮式 Toggle 在窗口不是 key 时不显示着色，离屏渲染里开和关是同一种灰，看不出线路是否在用。

哪条线路是主、哪条待命，面板和概览各算各的会不一致，所以抽成一个纯函数，两边共用。

## 完成定义（动工前冻结；实现中不得放宽）

- **D1** 线路的角色只由聚合方式、启用顺序和「仅备用」决定：主备下第一条非仅备用的启用线路是「主」，其余启用线路「备」；其他聚合方式下仅备用的线路是「备」（只要还有别的线路在承载），其余在承载；全部是仅备用时第一条承担流量；未启用的线路是停用。只有一条线路、没有聚合方式时它在承载。
  - 检：test `linkStandingFollowsModeOrderAndBackup`
- **D2** gate 全绿；测试计数只因本卡新增的测试而增加，既有测试没有被弱化。
