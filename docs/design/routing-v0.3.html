设计稿 v0.3 · 路由 · 替换 v0.2 的「节点」与「规则」两页

一眼看出：哪类流量，走了哪条路

现在的节点页把十几个分组平铺成卡片墙：分组套分组（proxy 里有 DE Auto，DE Auto 里又有节点），选中的是哪个节点要一层层点开；色点看不出含义；规则页只是一张表，看不出某条规则的流量最后从哪出去。v0.3 把两页合成「路由」，从「流量」出发，而不是从「节点」出发。

路线图左边是流量类别（由规则推出），中间是它落到的出口分组，右边是最终节点。连线宽度 = 实时速率，和概览的桑基图同一种语言。
展平的出口链每个分组只显示一行：proxy → DE Auto → DE‑1 AnyTLS · 368 ms。嵌套分组不用再一层层点开。
按地区与延迟挑节点选节点时按地区筛、按延迟排，顶上一条延迟分布图；147 个节点的分组也能三秒内选好。
试一下输入域名或选一个 App，逐步显示命中的规则、经过的分组、最终节点和线路，每一步写清「为什么」。
改走在任一流量类别上「改走 → 另一个分组」，不用改 JSON。改动存成覆盖层，订阅更新也不会冲掉（需要你确认，见文末）。
和连接页互通连接检查器里点「这条为什么走这里」，跳到试一下并带上这个目标。

主窗口 · 路由 › 试一下

这条流量为什么走这里

输入域名、IP 或在下拉里选一个 App（来自最近的连接）。不发起连接，只让内核按当前配置走一遍匹配，逐步列出结果。连接页检查器的「为什么走这里」也打开这一页。

每一步都说「为什么」 规则：第 7 条 rule_set=geosite-youtube，前 6 条为什么没命中可展开查看。分组：手动选择 / 延迟最低（附测速时间）/ 主备的第一个可用。线路：聚合方式与这条连接实际用的线路。

实现说明 libbox 1.14.4 没有「按配置解释匹配」的接口。在 pxbridge 里加一个导出，拿到扩展里运行中的 router，对构造的元数据调用匹配并记录每一步（Surge Mac 6.9 的 rule explain 是同样的思路）。
检查器 · 出口分组

一个分组一张选择器，不再是卡片墙

从地区筛选开始（从节点名里的旗帜与地名推断），按延迟排序，顶上是延迟分布。分组里还有分组时（proxy → DE Auto），子分组作为一行出现并显示它此刻选中的节点，点开在原地展开，不跳页。自动分组（urltest）不让点选节点，而是显示「自动选中了谁、为什么」，提供「固定使用某个节点」的入口。

三个决定

1 · 侧栏从九项变八项「节点」与「规则」合成「路由」。这改了决策 7 的「主窗口九项侧栏」。
2 · 「改走」的覆盖层覆盖存在 App 里，连接时由组合器把对应规则的 outbound 换掉（与线路组合同一处）。用户的配置文件不变、订阅更新不冲掉；但 App 里看到的路由会和配置文件不一致，需要明显标注「已覆盖」。这是新的存储格式（AGENTS.md 要求先讨论）。
3 · 流量类别怎么命名规则本身没有名字。默认用规则条件生成（geosite-youtube → YouTube，geoip-cn → 中国大陆 IP）；可以手动重命名，名字同样存在覆盖层里。
参考：Surge Mac 6.9 的 rule explain（逐步解释匹配的规则与分组决策）、Surge Dashboard 与 Stash 的请求列表。Parallux 独有的是把规则、分组、节点、线路画在同一张流向图里。
